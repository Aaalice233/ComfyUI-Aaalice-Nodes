# 参数系统设计规范

本规范覆盖 ParameterPanel、ParameterReceiver 及其结构编辑和双模式布局。参数身份、序列化和显式同步协议以 ADR 为准；本页只规定用户可见的交互与布局。

## 共同边界

- ParameterPanel 负责参数创作与直接输出；ParameterReceiver 只负责把当前图中的 KJ Get 收束为紧凑透传节点。接收器可绑定当前图或父级图中的面板，遵循 KJNodes 的 Set 向下可见、Get 向上查找作用域。
- 节点面用于高频调值和状态查看；新增、删除、重排、绑定、同步等结构操作进入右键菜单或专用弹窗。
- Canvas/native 层负责真实 slot、连线和静态布局；DOM overlay 负责控件、焦点、键盘、tooltip 和 aria。
- Classic 使用 LiteGraph 原生 slot；Nodes 2.0 使用 Vue slot DOM。不得绘制伪 socket。
- 前端只物化当前业务项对应的连续原生槽；后端有界协议中未使用的位置不进入画布槽数组。

## ParameterPanel 节点面

- 节点只显示参数值控件和真实输出，不放结构工具栏。
- 节点背景、外轮廓和顶部圆角完全沿用 ComfyUI 原生节点；DOM 根保持透明，不绘制第二层灰色主体或方形外框。
- 参数区左侧保留安全边距，右侧为输出名称和 socket 预留独立 gutter。
- 参数行与输出栈由同一布局引擎计算；节点高度取可见控件与输出所需高度的较大值。
- 只有产生值的参数创建输出；Separator 不创建画布槽。

### 参数控件

- ParameterPanel 节点面和 DIY 侧边栏中的 Aaalice 参数必须复用同一 Control Spec / Port / View 控件实现；宿主只负责标题、卡片布局、图事务和本地化文案，不复制 Slider、Seed、Switch、Enum、TagList 或图像控件。
- Slider 名称与数值同排，轨道位于下方并占满内容宽度；拖动立即更新，点击数值才进入编辑。
- Slider 的进度、滑块、普通开关开启态和输入焦点使用当前节点强调色；关闭态保持中性，错误和警告保留语义色。
- Dropdown 始终使用 select；Enum 默认在不超过 4 项时使用分段按钮，更多选项回退为 select，也可在参数设置中强制使用下拉框。该显示策略由节点和侧边栏共同遵循；分段按钮在 Hover / Focus 时显示完整选项名称。每个稳定枚举值自动映射到共享 12 色主题色板，切换时选择指示器随选项改变颜色，颜色不写入工作流；展开、关闭、Escape 和 change 后箭头状态必须同步。
- 动态选项来源通过独立适配注册表读取当前 ComfyUI `/object_info` 中对应节点输入的 Combo 定义，确保值与目标节点一致；新增来源只登记稳定 id、本地化名称和一个或多个节点输入映射。来源只有解析到非空选项时才出现在编辑器中；已有工作流引用的来源失效时只保留禁用的当前项，避免把真实状态伪装成“自定义”。当前支持 WD Timm Tagger 的反推模型，以及提示词助手的扩写规则、LLM 服务、反推规则和 VLM 服务。
- Switch 使用真实按钮和 `aria-pressed`；轨道可以使用胶囊形。
- Seed 的执行后行为按钮内嵌输入框尾部；点击后以共享 Popover 提供固定、递增、递减、随机四种模式，按钮图标与低强度语义色必须同步反映当前模式。随机模式保持中性输入表面，固定、递增和递减分别使用蓝、绿、琥珀色的低饱和输入底色，不能只靠图标区分。
- 文本、数字和下拉输入使用内嵌表面；hover 和编辑态才适度提亮。
- TagList 使用单行追加式组合框：已有标签与输入光标处于同一容器，按回车创建后继续在末尾输入；内容超宽时横向滚动，不额外增加参数行高度。标签文本通过稳定哈希自动映射到主题色板，同一控件的前 12 个不同标签优先使用不同识别色，颜色不写入工作流。单击标签切换是否参与输出，删除与拖拽排序直接作用于当前参数。停用标签继续随工作流保存，但直接输出只包含仍启用的标签文本；旧版纯字符串数组按全部启用读取。
- 临时数字编辑器使用不透明高对比表面，隐藏原生微调箭头和底层静态数值。
- 图像参数与侧边栏公开的可编辑图像 Combo 复用同一双入口控件：主区域打开图像资源浏览器，并按全部、已导入和已生成筛选；右侧文件夹按钮只负责本机上传。资源浏览器使用 ComfyUI 的输入文件与最近历史公共数据源，保留搜索、排序和网格/列表切换，不依赖前端私有 Vue 组件。文件拖放与右侧上传复用同一校验和持久化链路；拖入时显示节点强调色反馈并拦截画布全局 drop，上传成功使用原生 Toast。缩略图居中裁切，悬浮或聚焦时显示完整预览和独立清空按钮。
- 参数说明 tooltip 使用紧凑行宽和清晰 Markdown 层级，不能大面积遮挡后续控件；标准 HTTP(S) Markdown 链接可由鼠标点击或从说明按钮按 Tab 进入，并在移入浮层期间保持显示。
- 所有控件保留键盘焦点、本地化 aria 名称和至少 32px 命中区。

### 侧边栏分区投影

- Separator 只定义其后参数的语义分区，不生成侧边栏参数卡片；前置参数属于面板根分区，连续、开头或末尾 Separator 形成的空分区不显示。
- “添加参数到侧边栏”按原顺序显示分区标题，标题使用 Separator 显示名；面板存在 Separator 分区时只创建对应的 Dashboard 来源组，不自动创建 Dashboard 分隔项。普通显示和布局模式均按组设置显示组标题，编辑模式保留组头和组操作。
- 分区来源身份由面板稳定 Host Id 与 Separator 的稳定 Parameter Id 共同构成，显示名不参与匹配。来源组记录 `group.source`，纳管卡片记录 `groupSource`；Separator 改名、参数增删、重排或类型变化只把来源组标记为“需要同步”，由组头按钮或当前页右键菜单显式提交。侧边栏用户显式改过的标题保留不变。
- 只要面板存在承载参数的 Separator 分区，根分区与每个 Separator 分区都会各自自动成组，单参数分区也不例外；无 Separator 面板仍在同源参数达到两个时自动成组。来源组标题右侧状态按钮使用 `statusCheck`、`refresh`、`statusWarning` 和 `statusError` 表达同步状态；手动组不显示来源同步入口。
- 自动分组只处理本次新增的卡片并复用完全匹配的来源组，不迁移、拆分或整理现有布局；新建分区组的成员先在组内从左上角按原顺序紧凑排布。Dashboard 命令只消费通用来源分组提示，不直接读取 ParameterPanel 参数结构。显式同步按稳定 Binding 顺序新增、直接删除明确纳管且已不存在的卡片、更新类型和未覆盖名称，并重排纳管卡片；保留卡片尺寸、组位置/宽度和手动成员。
- 布局组使用页面 12 列网格的真实 `columnSpan`：新建或旧版满宽组按成员占用范围自动紧凑，单列/单卡组不会保留无意义的右侧空白；布局模式下可通过组框右下角手柄或左右方向键调整宽度，最小值受成员范围约束，组高仍由成员内容自动派生。运行时兼容旧占位变高时，组内和页面级投影统一消解碰撞，组间视觉间隔不由 DOM 测量或临时 margin 决定。ParameterPanel Separator 只作为来源组作用域，不进入 Dashboard 分隔项。
- 侧边栏卡片使用 Dashboard V3 整数网格：宽度为 3–12 的任意整数列跨度，行高为不小于 13 的任意整数跨度；6 列、13 行等只是不同控件的推荐默认。拖拽、键盘和命令统一按整数单位吸附，来源同步与预设恢复保留有效跨度。V2 读取时自动迁移为 V3，旧双列的列位置与列跨度等比映射到 12 列，原有有效整数行跨度保持。Provider 如需适配动态内容，只返回非持久的 `layoutProjection`；页面与组内按投影重排显示占位，不覆盖卡片的规范布局。

## 参数结构编辑器

- 标题栏只显示“编辑参数”和参数数量，不重复节点名称或产品说明。
- 宽屏采用参数列表与 inspector 双栏；窄屏改为上下布局。
- 左栏负责新增、选择、重排、复制和删除；次要动作默认弱化。
- 参数类型选择与新增按钮组成连续控件，并保留至少 40px 命中高度。
- inspector 直接从字段开始，不重复无信息增量的卡片标题。
- Markdown 说明框在宽屏中填满可用高度并内部滚动；窄屏保持稳定高度。
- Slider 的 min / max / step 三等分；Seed 的 min / max 二等分；数字使用 tabular numerals。
- Footer 固定承载草稿状态、校验错误、取消和保存。
- 删除已连接参数时列出受影响连线并确认；保存后原子应用为一个图变更边界。

## ParameterReceiver

- 最小宽度为 220px，新建节点默认宽度为 280px；标题下显示一行弱化绑定信息，中部排列真实输入/输出，异常状态使用紧凑图标入口。
- 节点面不放结构操作按钮；绑定、同步、定位和解除进入带 emoji 的本地化右键菜单。ParameterPanel 菜单提供全部已绑定接收器的一键同步与定位，接收器菜单提供反向定位。
- “已同步”使用成功语义；“需要同步”使用警告语义；源缺失和 KJNodes 缺失必须有文字说明。
- 参数或面板改名属于显示同步：面板输出、对应 KJ Set、托管 Get 与接收器同名输入/输出必须在同一更新链中刷新，不要求用户再次执行结构同步。侧边栏来源组名称同步属于独立的显式 Dashboard 同步事务，不随 ParameterPanel 事件自动改写工作流布局。
- 面板的“创建并连接 KJ Set”和“同步参数接收器”都会按当前参数顺序整理直接关联的主 Set；不同图作用域各自保持一列。接收器同步同时按相同顺序整理其托管 Get。
- 折叠 Get 按输入行垂直排列在接收器左侧，并保留稳定间距。
- Set/Get 被收进下级子图时，通过真实 Subgraph 输入输出槽继续纳管；作用域明确时，新增参数沿用既有 Set/Get 所在图，不把节点静默移回外层。
- 输入与输出数量等于当前 Receiver Binding 槽数；节点最小高度由真实输入行和状态区计算。

## 尺寸与 Nodes 2.0

- `computeSize()` 只返回内容下限，不能把当前 `node.size` 当成最小值。
- DOM widget 通过 `getMinHeight()` 声明内容下限；用户拉大后必须能够重新缩小到真实内容高度。
- 参数控件与原生 slot 共用相同行区，布局高度取两者较大值，不得把 slot 栈和 DOM 内容高度相加。
- 内容增长时 Classic 可使用 grow-only 布局路径；Nodes 2.0 由 DOM 测量持有尺寸真源。
- 用户拖拽期间不得在延迟回调中反复 `setSize()`，也不得让全尺寸 DOM widget 吞掉 LiteGraph 原生缩放角。
- Nodes 2.0 重建 slot DOM 后，只恢复业务布局所需的位置和 class；不得恢复已删除的隐藏槽协议。
- Classic 不得用固定菜单表面覆盖 LiteGraph 的节点主体；Nodes 2.0 不得把原生节点或标题容器的顶部圆角强制改为方角。

## 验收重点

- 名称、控件、输出文本和 socket 不重叠或截断。
- 参数或面板改名后，Set、托管 Get 与 Receiver 槽名称保持一致；重排和 Receiver 显式同步后，连线仍跟随稳定 Parameter Id。
- Seed、数值编辑、枚举、动态选项、绑定状态和原生 socket 在 Classic 与 Nodes 2.0 中一致。
- 修改和清除节点颜色后，控件强调色即时同步且语义状态颜色不被覆盖。
- 保存重载、复制、撤销和重做后，状态、槽数量、顺序和节点尺寸一致。
