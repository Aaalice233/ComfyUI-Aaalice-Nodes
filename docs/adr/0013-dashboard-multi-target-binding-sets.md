# ADR 0013：Dashboard 使用主参数与多目标绑定集

**Status:** Accepted

## Context

Dashboard 原先把一张参数卡片等同于一个 Binding，适合单节点调参，但无法让一个侧边栏控件同时驱动多个节点参数。若只在 renderer 或 Workspace 的 `setValue()` 外层临时循环，会让持久模型、预设、来源同步、撤销事务和错误回滚继续各自假设“单卡单目标”：第三方写入中途失败会留下部分状态，Seed 的数值与执行后行为可能分离，来源参数删除还可能误删整张联动卡片。

另一种方案是新建独立“联动节点”或复制卡片并让卡片互相引用。这会产生第二份参数状态或循环引用，并把图执行职责引入纯 UI 投影；因此不采用。

## Decision

Dashboard V4 为控件项保留唯一主 `binding`，并增加有序 `linkedBindings`。主 Binding 唯一拥有卡片标题、说明、Control Spec、显示值和来源组身份；附加 Binding 只表示相同用户输入的写入目标，不拥有独立卡片状态。V2/V3 读取时自动迁移为 V4，原 Binding 和布局保持不变。

`js/lib/control_binding_set.js` 是运行时联动的唯一协调边界。目标必须：

- 位于同一 ComfyUI graph；
- 由 Provider 声明为可联动、可读写并可进入预设；
- 解析成相同 Control Spec 类型、值类型和有效值域；数字还必须保持 Integer / Float 域一致，图像选择器必须保持目录与上传子目录一致，但不把可随上传刷新的文件列表当作持久兼容签名；
- 对 Seed 同时支持数值与 `control_after_generate` 的读取、校验和写回；每次 `graphToPrompt` 序列化前及 `queuePrompt` 完成后都以主 Seed 重新收敛整组，覆盖 `before` / `after` 模式、多批队列与工作流切换，避免实际 prompt 或下一次值漂移。

运行时 `availability` 与 Binding 健康度分离：暂无动态选项、尚未选择或临时不可用不会删除或判坏关系，但整张卡片暂时停止写入并显示可恢复状态；只有 Binding 缺失、接口消失或结构契约漂移才进入联动错误。

一次联动写入先快照全部目标，再在一个 graph history 边界中逐项写入。任一目标抛错、返回显式失败或先修改后失败时，协调器逆序回滚全部已触达目标；renderer、Workspace 和业务节点不得自行实现循环写入。

节点右键菜单在 Provider 实时发现控件后分别提供“添加到侧边栏”和“绑定到已有侧边栏参数”。卡片保留主参数重绑和附加目标解除入口。值不一致时卡片继续显示主值并标记 Mixed，不自动猜测覆盖方向；用户写入卡片或显式“以主参数同步”后才统一目标。

侧边栏预设展开主 Binding 与全部附加 Binding，并按稳定 Binding Key 全局去重后捕获、预检、应用和回滚。Binding Key 使用字段元组编码，不能靠冒号拼接第三方可控字符串；读取旧预设时自动迁移旧 Key。来源同步只用主 Binding 认领卡片；来源删除或类型漂移时，含附加目标的卡片必须保留并解除来源纳管，不能整体删除。Subgraph 仍只允许宿主公开的 widget，禁止直接穿透内部节点。

## Consequences

- 一个侧边栏控件可以安全控制多个兼容节点参数，同时保持节点参数仍是唯一值真源。
- 工作流、复制、撤销/重做和便携预设需要理解完整 Binding Set；旧版插件无法读取保存后的 V4 数据。
- 严格值域检查会拒绝看似同为数字但 Integer / Float 域、范围、步长或 Seed 语义不同的目标，减少静默截断和行为漂移。
- 缺失或结构失效的附加目标会禁用整组写入，直到用户解除或修复；系统不会跳过坏目标制造部分成功。临时不可用只暂停写入，不破坏持久关系。
- 第三方适配器只有显式声明 `linkable: true` 且提供可回滚同步 codec 时才参与联动；其余适配器保持不可联动。
