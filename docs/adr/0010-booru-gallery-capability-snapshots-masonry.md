# ADR 0010：Booru Gallery 使用能力适配、选择快照与虚拟瀑布流

Status: Accepted.

## 背景

不同 Booru API 的分页、Rating、认证、标签分类和收藏能力并不等价。把站点判断散落在界面和路由中会让新增来源持续扩大分支；执行时重新读取当前帖子又会使已排队任务随远端或节点后续编辑变化。普通定高虚拟列表无法保留画廊图片的自然宽高比。

## 决策

每个来源通过固定适配器方法和 `GalleryCapabilities` 声明能力，核心层只消费统一 Summary、Detail 与 Page。排行榜作为独立频道能力声明，不伪装成普通搜索排序；首版 Danbooru 提供周榜、月榜，AI TAG 提供月榜。界面页码统一从 1 开始，适配器负责换算站点的 `page`、`pid` 或未来 cursor；只有 capability 声明可直接跳页时才显示页码输入。搜索结果保持轻量，详情和分类标签按需补全并进入有界缓存。工作流只保存有序选择快照；`graphToPrompt` 为每次排队物化独立的版本化 payload 和最终 Prompt。浏览区使用独立的最短列虚拟瀑布流，按 API 宽高计算位置，只挂载视口和 overscan 范围内的图片 DOM。

## 结果

- 站点差异集中在适配器和 capability，不用在核心界面散布来源判断。
- 已排队任务拥有确定的图片顺序和标签编辑结果；凭据、缓存和临时搜索状态不进入工作流。
- 深翻页的布局数据线性增长，但详情文本、图片 DOM 和网络并发保持有界。
- 节点只持久化当前逻辑页码，不持久化结果、cursor 或滚动像素；切换查询上下文回到第 1 页，刷新保留当前页，直接跳页不补载前面的页面。
- 不提供旧 ID、旧设置或选择 FIFO 的迁移，也不使用 Cookie、HTML 会话和验证码绕过缺失 API。
