# ADR 0011：Krita Bridge 使用短请求快照与显式失败

- 状态：Accepted
- 日期：2026-07-20

## 背景

`FetchFromKrita` 需要在工作流真正执行时读取 Krita 当前活动文档，而不是保存一个容易失效的文件路径、界面预览或工作流内图像副本。当前工作方式由用户先在 Krita 中准备文档和选区，再回到 ComfyUI 执行，因此 Bridge 只需要承担单向快照获取，不需要反向发送或双向编辑会话。

## 决定

1. 随包提供独立插件 `aaalice_comfy_bridge`。安装和修复只能由用户在共享 Krita 设置中显式触发，并同时原子写入 Krita 的插件启用项；节点不启动、关闭或定位 Krita。
2. ComfyUI 与 Krita 只在专用临时目录中交换原子 JSON 和请求专属 PNG，不开放本地端口。请求和响应都携带协议版本与唯一 `request_id`，媒体路径必须落在 Bridge 临时目录内。
3. `FetchFromKrita` 是零输入外部源节点。每次执行创建一个 15 秒以内的 `fetch_snapshot` 请求，读取当前活动文档的可见合成图和当前选区，并在完成、失败、超时或取消后只清理本次请求的数据。
4. 没有选区与合法全黑选区是不同状态：前者生成同尺寸全黑 `MASK`，后者保留 Krita 实际导出的全黑选区及“选区存在”元数据。
5. Krita 未运行、Bridge 缺失或不兼容、没有活动文档、导出失败、路径或尺寸校验失败以及超时都使节点明确失败，不返回空图、旧快照或其它备用值。
6. Bridge 状态与最近一次执行摘要只用于界面反馈，不进入 `node.properties` 或工作流 JSON，也不能代替执行时重新读取。

## 影响

- `FetchFromKrita` 的结果不可缓存；V3 节点使用外部状态失效标记保证每次排队都重新请求。
- 短文件协议允许并发节点按请求身份隔离，也避免常驻网络服务和端口配置。
- 用户显式安装或修复时由 ComfyUI 同时启用 Bridge，之后启动 Krita 即可；覆盖 Bridge 文件或配置前必须先关闭 Krita。
- 当前能力只面向同一台机器上的一个活动文档，不提供文档选择、批量抓取、图层选择、Krita 启动或双向编辑会话。
