# ADR 0014：侧边栏仅数值导入使用唯一语义恢复

**Status:** Accepted

## 背景

侧边栏便携预设按稳定 Binding Key 保存参数值。工作流升级若重建节点、子图宿主或公开 widget，旧预设的 Host ID、Adapter ID 或 promoted source identity 可能整体变化；即使新版侧边栏仍表达相同参数，纯精确匹配也只能保留目标原值。

按数组位置、卡片顺序或单一显示名称迁移会把旧值静默写入错误参数。完整布局导入还会把旧版失效 Binding 一起带回新版工作流，破坏新版布局已经完成的绑定修复。

## 决策

普通 Dashboard Binding 解析、预设切换和完整预设导入继续遵循 ADR 0008 的稳定身份契约。外部预设导入默认使用“仅导入数值”；仅当工作流没有可作为基础的预设时，界面默认回到完整预设导入。两种模式都要求命名并额外创建预设，绝不覆盖已有预设。

仅数值导入先复制用户选择的基础预设，以该副本的 Dashboard 为权威，再按以下顺序规划：

1. 先按完整 Binding Key 精确匹配。
2. 对仍未命中的控件，按源、目标快照中的卡片关系分层匹配：已有 Binding 锚点、稳定卡片 ID、同一 Host、同一页面与布局组上下文、最后才是全局卡片语义。
3. 除 Binding 锚点外，候选必须匹配 Provider、`valueType` 和规范化 Control 名称。稳定 Card ID、同一 Host 或同一页面/布局组上下文可在卡片改名后提供约束；脱离这些结构上下文的全局候选还必须匹配保存的卡片标签。每一层都要求源卡片与目标卡片互为唯一候选。
4. 一张卡片匹配成功后，目标 Binding Key 缺失的成员使用源卡片中主绑定优先的首个可用值，填充新版卡片新增或改名后的 primary / linked Binding；仍有精确 Key 的成员保持精确值。写入继续逐个使用目标 Binding 和目标 Provider。
5. 不使用页面内顺序、数组下标、节点位置或仅凭标题的近似匹配。任何重复候选、类型漂移、Provider 不可用或 codec 拒绝都进入预览并跳过，目标原值保持不变。

导入解析按单个值隔离无效 payload；一个 `NaN`、`Infinity`、不安全对象键或损坏条目不能阻止其余有效布局和值进入预览。Dashboard 结构、备份格式和版本仍严格校验。

确认时重新解析全部目标 Provider 和 preset codec。新副本持久化、切换到副本 Dashboard 与节点写入保持在同一回滚边界；任一写入失败时删除未完成副本，并恢复导入前 Dashboard、基准身份和已触达节点值。基础预设及其快照始终不变；导入前 Working Copy 仅作为回滚对象，不参与副本构造。确认成功后，新副本成为当前 Dashboard 和当前基准，用户看到的正是刚创建的结果。

完整预设预检若发现 Missing、类型不兼容或解析失败的 Binding，导入界面必须明确说明新预设会保留失效组件，并在用户坚持导入时再次确认。预览聚合显示可导入、可安全恢复、跳过和需要处理的数量，具体问题按需展开。

## 结果

- 工作流重建稳定身份但保留参数语义时，旧预设可迁移可唯一确认的值。
- 新版 Dashboard 始终拥有布局和 Binding；旧文件不能修改基础预设、创建旧卡片或写入基础预设之外的节点；成功后只切换到新副本。
- 重复名称和不确定映射会显式跳过，无法获得“尽量成功”但可能错写的结果。
- 语义恢复依赖旧快照仍保留 Provider、类型、Control 名称和卡片上下文；这些字段同时漂移时仍需人工处理。
- 完整预设导入保持可用，但失效 Binding 风险在确认前可见；仅数值导入是默认且不覆盖任何已有预设。
